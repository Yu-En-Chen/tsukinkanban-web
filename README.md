## 日本語

### このアプリが解決したいこと

既存の交通アプリは「路線」を登録する仕組みです。多くの人は通勤で使う数路線だけを登録して終わりですが、実際の生活には通勤以外にも**決まった移動**がたくさんあります。月に一度の帰省、週末のお出かけ、子どもの送り迎え、空港への移動——。

そして、こうした移動には路線にはない性質があります。**乗り継ぐ路線のどれか一つでも止まれば、その移動全体が成立しない**ということです。知りたいのは「山手線が今どうか」ではなく、「今日、この移動がスムーズにできるか」のはずです。

**通勤看板**は、移動情報の単位を「路線」から「シーン」に置き換えた Web アプリ（PWA）です。

### 仕組み

- 一枚のカード ＝ 一つのシーン（例:「通勤」「帰省」「週末の横浜」）
- 各カードには、そのシーンで使う路線・フライトを最大 6 つまで登録できます
- カードの表面にはランプ（SVG インジケーター）があり、シーン全体の状態を集約して表示します

つまり、カードを**開かなくても**、画面をひと目見るだけで「今日の自分の移動のうち、どれが順調でどれが危ないか」がわかります。ボードには 5 枚のカードを置けるので、生活の中の 5 つの決まった移動を一画面で見渡せます。

初期状態のカードと路線はデモ用のスターターデッキです。**カード名・路線・カラーはすべて自由に入れ替えられ**、自分だけのデッキを組むことができます。

### 主な機能

| 機能 | 説明 |
|---|---|
| シーンカード | 最大 6 路線を一枚のカードにまとめ、カードスタックで表示。タップで各路線の詳細を確認できます |
| カード表面のランプ | カードを開かずに、シーン全体の運行状態をひと目で把握できます |
| フライト対応 | 鉄道だけでなく、ANA・JAL など国内線の運航状況もカードに登録できます（羽田・成田） |
| 路線検索 | ヘッダーの検索からインクリメンタルに路線を検索・追加 |
| パーソナライズ | カードの表示名やカラーを自由にカスタマイズ（端末内保存） |
| 同期時計 | 最終データ同期時刻を常時表示。同期が途切れると色で警告します |
| 履歴 | 過去の運行情報を時系列で振り返ることができます |
| 取り消し | パーソナライズ変更のワンタップ・アンドゥ |

### プライバシー

- 会員登録不要・広告なし・サードパーティ Cookie なし
- デッキの内容やパーソナライズ設定はすべて端末内（ブラウザ）に保存され、サーバーには一切送信されません
- ホーム画面に追加すれば、ネイティブアプリのように利用できます（PWA 対応）

### データソース

交通データは **公共交通オープンデータ協議会（[ODPT](https://www.odpt.org/)）** より提供されています。対応路線の一覧はアプリ内「データソース」ページをご覧ください。

> 本サービスは個人が開発・運営する**非公式**のサードパーティアプリであり、ODPT および各鉄道・交通事業者とは一切関係がありません。

### 技術構成

- **フレームワークなし** — 素の HTML / CSS / JavaScript（ES Modules）のみで構築。ビルド工程は不要です
- **PWA** — `manifest.json` によるホーム画面追加・スタンドアロン表示に対応
- **アイコン** — [Lucide Icons](https://lucide.dev/)（SVG インライン埋め込み）
- **状態保存** — `localStorage` / ブラウザ内 DB のみ。サーバー側にユーザーデータは保存しません

### ディレクトリ構成

```
tsukinkanban-web/
├── index.html          # エントリーポイント（アプリシェル）
├── manifest.json       # PWA マニフェスト
├── css/                # スタイルシート（変数・アニメーション・各 UI 部品）
├── js/                 # アプリケーションロジック
│   ├── script.js       #   メインエンジン（カード描画・操作）
│   ├── header.js       #   ヘッダー・検索・カプセルボタンのモード切替
│   ├── clock.js        #   同期時計
│   ├── flights.js      #   フライトカード
│   ├── personalization.js  # カードのカスタマイズ
│   └── ...
├── data/               # 路線辞書・メニュー文言などの静的データ
└── img/                # ロゴ・画像
```

### ローカルで動かす

ビルド不要です。任意の静的サーバーでルートディレクトリを配信してください。

```bash
# 例 1: Python
python3 -m http.server 8000

# 例 2: VS Code の Live Server 拡張機能で index.html を開く
```

ブラウザで `http://localhost:8000` を開けば動作します（運行データの取得には外部 API への接続が必要です）。

## 繁體中文

### 這個 App 想解決的問題

現有的交通 App 都是以「路線」為單位：多數人只會把通勤用的那幾條線加進去，就結束了。但實際生活裡，除了上班之外還有很多**固定的移動**——每月回老家、週末出遊、接送小孩、跑機場。

而這類移動有一個「單一路線」沒有的性質：**只要其中任何一段誤點或停駛，整趟行程就不成立**。你真正想知道的從來不是「山手線現在怎樣」，而是「我今天這趟，順不順」。

**通勤看板**（つうきんかんばん）就是把交通資訊的單位從「路線」換成「場景」的行動網頁應用程式（PWA）。

### 運作方式

- 一張卡片 ＝ 一個場景（例如「上班」「回老家」「週末去橫濱」）
- 每張卡片最多可放入 6 條該場景會用到的路線或航班
- 卡片正面有燈號（SVG 指示燈），聚合顯示整個場景的運行狀態

也就是說，**不用點開卡片**，掃一眼畫面就知道「今天我的哪條動線是綠的、哪條有狀況」。看板上可以放 5 張卡片，等於把你生活中 5 條固定動線收進同一個畫面。

初始畫面上的卡片與路線只是展示用的起手牌組，**卡片名稱、路線、顏色全部都能自由替換**，組出完全屬於自己的牌組。

### 主要功能

| 功能 | 說明 |
|---|---|
| 場景卡片 | 一張卡片最多整合 6 條路線，以卡片堆疊呈現，點開可看各路線詳細資訊 |
| 卡面燈號 | 不點開卡片，也能一眼掌握整個場景的運行狀態 |
| 航班支援 | 不只鐵路，ANA、JAL 等日本國內線航班也能放進卡片（羽田、成田） |
| 路線搜尋 | 從頂部搜尋列即時搜尋並加入路線 |
| 個人化 | 自訂卡片的顯示名稱與顏色（僅存於裝置內） |
| 同步時鐘 | 常駐顯示最後資料同步時刻，同步中斷時以顏色警示 |
| 歷史紀錄 | 依時間軸回顧過去的運行資訊 |
| 復原 | 個人化變更可一鍵復原 |

### 隱私

- 免註冊、無廣告、不使用第三方 Cookie
- 牌組內容與個人化設定只存在你的裝置（瀏覽器）內，不會上傳到伺服器
- 支援 PWA，加入主畫面後可像原生 App 一樣使用

### 資料來源

交通資料由**公共交通開放資料協議會（[ODPT](https://www.odpt.org/)）**提供。支援路線清單請見 App 內的「資料來源」頁面。

> 本服務為個人開發、營運的**非官方**第三方應用程式，與 ODPT 及各鐵路、交通業者皆無任何關係。

### 技術架構

- **無框架** — 純 HTML / CSS / JavaScript（ES Modules），不需要任何建置流程
- **PWA** — 透過 `manifest.json` 支援加入主畫面與獨立視窗顯示
- **圖示** — [Lucide Icons](https://lucide.dev/)（以行內 SVG 嵌入）
- **狀態儲存** — 僅使用 `localStorage` 與瀏覽器內建資料庫，伺服器端不儲存任何使用者資料

在瀏覽器打開 `http://localhost:8000` 即可運作（取得即時運行資料需要能連上外部 API）。
