## 日本語

### このアプリが解決したいこと

首都圏の移動は、相互直通運転や乗り継ぎによって、一つの移動に複数の事業者・路線が関わります。一方で運行情報は事業者・路線ごとに発信されるため、「自分の移動に関わる路線はどれで、すべて問題ないか」を毎回自分で組み立て直す必要があります。

しかも生活の中には、通勤以外にも決まった移動があります。月に一度の帰省、子どもの通学、家族の通院、空港や島へのアクセス。こうした移動は通勤ほど意識が向かず、確認も後回しにされがちです。

知りたいのは「山手線が今どうか」ではなく、「今日、この移動がスムーズにできるか」のはずです。**通勤看板**は、運行情報の単位を「路線」から「いつもの移動（シーン）」に組み替えた Web アプリ（PWA）です。

### 仕組み

- 一枚のカード ＝ 一つの移動（例：「平日の通勤」「子どもの通学」「伊豆大島へ」）
- 1 枚のカードに、事業者の異なる鉄道・バス路線、東海汽船の航路を最大 6 つまで登録でき、鉄道・バス・船を混在できます
- フライトは情報量が多いため、1 便ごとの専用カード・専用レイアウトで表示します（鉄道・バスのカードと同じボードに並べられます）
- カード表面のランプが、移動全体の状態を〇△×で集約して表示します

カードを**開かなくても**、画面をひと目見るだけで「今日の自分の移動のうち、どれが順調でどれに注意が必要か」がわかります。ボードには最大 5 枚のカードを表示できます。

初期状態のカードと路線はデモ用のスターターデッキです。**カード名・路線・カラーはすべて自由に入れ替えられ**、自分の生活に合わせたボードを作れます。

### ランプの見方

| 記号 | 意味 |
|---|---|
| 〇 | 平常（鉄道は遅延 5 分以内、船は運航予定） |
| △ | 遅れ（鉄道は 6〜15 分）、遅延・見合わせ等の発表、船の条件付き運航・出帆港変更・一部欠航 |
| × | 大幅な遅れ（鉄道は 16 分以上）、船の欠航、情報取得エラー |
| 吹き出し | お知らせの発表、情報確認中、データの提供期間が終了した路線など |
| 地震・雨風・雪 | 運行情報に該当する記述があるときのみ表示 |

記号の形、点灯／消灯の明るさ、ランプ横の文章でも状態を伝えるため、色だけに頼らずに読み取れます。

船は、欠航で ×、条件付き運航・出帆港変更・一部欠航（区間欠航・寄港取りやめ）で △、就航判断待ち・出帆港未定などは吹き出しで表示します。本日運航がない航路や、時刻表のみのバスで本日の便がない場合も × になります。

|---|---|

| カード表面のランプ | 〇△×の記号と文章で、移動全体の状態をカードを開かずに把握できます |
| 鉄道の遅延分数 | JR 東日本・東武鉄道・都営地下鉄・横浜市営地下鉄は、列車ロケーション情報から方向別の遅延分数を表示。湘南新宿ライン・上野東京ラインは直通列車を判定して運転系統単位で集計し、どの区間の遅れかを示します |

| フライト | 羽田・成田の出発便・到着便に対応。JAL・ANA 便は搭乗口・ターミナル情報もあわせて表示します（Beta）。更新が 15 分以上途絶えた場合は、情報が古い可能性を表示します |
| 空港へのナビゲーション | フライトカードから Google マップを起動し、空港・ターミナルへの経路案内を開始できます |

| 路線検索 | ヘッダーの検索から、鉄道・バス・船・フライトをインクリメンタルに検索・追加できます |

| 履歴 | 過去の運行状況を時系列で振り返ることができます（船は当日の運航情報の移り変わり） |

### プライバシー

- 会員登録不要・広告なし・サードパーティ Cookie なし
- カードの内容やパーソナライズ設定は端末内（ブラウザ）にのみ保存され、サーバーには一切送信されません
- 位置情報は取得しません
- 設定の引き継ぎはクリップボード経由で行い、サーバーを経由しません
- ホーム画面に追加すれば、ネイティブアプリのように利用できます（PWA 対応）

### データソース

本サービスは、公共交通オープンデータセンターにおいて提供されるデータを利用しています。データは、必ずしも正確・完全なものとは限りません。本サービスの表示内容について、公共交通事業者への直接の問合せは行わないでください。

- 一部のデータ（JR 東日本・東武鉄道・西武鉄道・京急電鉄・京王電鉄・東急電鉄の運行情報、JR 東日本・東武鉄道の列車ロケーション情報、成田・羽田のフライト情報）は「公共交通オープンデータチャレンジ2026」限定で提供されているもので、2027 年 2 月末まで提供予定です。提供終了後は該当する路線を「提供終了」と表示し、終了の 30 日前から予告します
- 船・島しょ部のバスは、東海汽船（時刻表・運航情報）、大島旅客自動車（大島バス時刻表）、三宅村（三宅村営バス時刻表）のデータを利用しています
- 三宅村営バスの時刻表データ　出典：三宅村／公共交通オープンデータセンター（[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ja)）。本サービスで加工して表示しています
- 対応路線の一覧は、アプリ内「データ元」ページをご覧ください

> 本サービスは個人が開発・運営する**非公式**のサードパーティアプリであり、ODPT および各鉄道・交通事業者とは一切関係がありません。

### 技術構成

- **フレームワークなし** — HTML / CSS / JavaScript（ES Modules）のみで構築。動作にビルド工程は不要です
- **PWA** — `manifest.json` によるホーム画面追加・スタンドアロン表示に対応
- **状態保存** — IndexedDB（利用できない環境では localStorage）。サーバー側にユーザーデータは保存しません
- **通信の抑制** — バス・船のデータは、ボードに該当する路線・航路がある場合と検索時にのみ取得します
- **GTFS の取り込み** — 船・島しょ部のバスは GTFS 時刻表を利用。バックエンドが新しい版を毎日確認し、有効開始日に自動で切り替えます
- **アイコン** — [Lucide Icons](https://lucide.dev/)（SVG インライン埋め込み）

## 繁體中文

### 這個 App 想解決的問題

首都圈的移動因為直通運轉與轉乘，一趟移動常牽涉多家業者、多條路線。但運行資訊是依業者、依路線各自發布，使用者每次都得自己重新組合「我這趟會用到哪幾條、是不是全部沒問題」。

而且生活中除了通勤，還有其他固定的移動：每月回老家、小孩通學、家人就醫、前往機場或離島。這些移動不像通勤那樣受到關注，確認也常被往後排。

你真正想知道的從來不是「山手線現在怎樣」，而是「我今天這趟，順不順」。**通勤看板**（つうきんかんばん）就是把運行資訊的單位，從「路線」重組成「日常固定的移動（場景）」的行動網頁應用程式（PWA）。

### 運作方式

- 一張卡片 ＝ 一趟移動（例如「平日通勤」「小孩通學」「去伊豆大島」）
- 一張卡片最多可登錄 6 條不同業者的鐵道、巴士路線與東海汽船航路，鐵道、巴士、船可混合
- 航班資訊量多，以一班一張的專用卡片與專屬排版呈現（可與鐵道、巴士卡片排在同一個看板上）
- 卡片正面的燈號以〇△×彙整整趟移動的狀態

**不用點開卡片**，掃一眼畫面就知道「今天我的哪趟移動順利、哪趟需要注意」。看板上最多顯示 5 張卡片。

初始畫面上的卡片與路線是展示用的起手牌組，**卡片名稱、路線、顏色全部都能自由替換**，組出符合自己生活的看板。

### 燈號說明

| 符號 | 意義 |
|---|---|
| 〇 | 正常（鐵道誤點 5 分以內，船預定航行） |
| △ | 延誤（鐵道 6～15 分）、誤點或停駛等公告、船附條件航行、改港或部分停航 |
| × | 嚴重延誤（鐵道 16 分以上）、船停航、資料取得錯誤 |
| 對話框 | 有公告、資訊確認中、資料提供期間已結束的路線等 |
| 地震、雨風、雪 | 只在運行資訊有相關描述時顯示 |

以符號形狀、亮滅明暗、燈號旁的文字說明來傳達狀態，不只依賴顏色。

船班停航為 ×，附條件航行、改港、部分停航（區間停航、取消靠港）為 △，等待開航判斷、靠港未定等以對話框表示。當天沒有航班的航路，或只有時刻表的巴士當天沒有班次時，也會顯示 ×。

### 主要功能

| 功能 | 說明 |
|---|---|
| 場景卡片 | 最多 6 條鐵道、巴士路線或船的航路收進一張卡片，以卡片堆疊呈現，點開可看各路線詳情 |
| 卡面燈號 | 以〇△×符號與文字，不點開卡片也能掌握整趟移動的狀態 |
| 鐵道誤點分鐘數 | JR 東日本、東武鐵道、都營地下鐵、橫濱市營地下鐵由列車位置資料顯示各方向誤點分鐘數；湘南新宿線、上野東京線判定直通列車後以運轉系統為單位彙整，標示誤點區段 |

| 離島巴士 | 支援大島巴士、三宅村營巴士時刻表。三宅島會依當天船靠哪個港，自動判斷當天會開哪個港的班次 |
| 航班 | 支援羽田、成田的出發與抵達航班；JAL、ANA 航班一併顯示登機門、航廈資訊（Beta）；超過 15 分鐘未更新時提示資料可能過舊 |
| 機場導航 | 從航班卡開啟 Google 地圖，導航至機場或航廈 |
| 官網捷徑 | 直接開啟卡片內路線、巴士、航路業者的官方網站 |
| 路線搜尋 | 從頂部搜尋列即時搜尋並加入鐵道、巴士、船、航班 |
| 個人化 | 自訂卡片的顯示名稱與顏色（僅存於裝置內），變更可一鍵復原 |
| 同步時鐘 | 常駐顯示最後資料同步時刻，同步中斷時發出警示 |
| 歷史紀錄 | 依時間軸回顧過去的運行狀況（船為當天運航資訊的變化） |
| 設定匯出／還原 | 透過剪貼簿匯出、匯入設定 |

### 技術架構

- **無框架** — 純 HTML / CSS / JavaScript（ES Modules），執行不需要建置流程
- **PWA** — 透過 `manifest.json` 支援加入主畫面與獨立視窗顯示
- **狀態儲存** — IndexedDB（無法使用時改用 localStorage），伺服器端不儲存任何使用者資料
- **減少通訊** — 巴士與船的資料只在看板上有對應路線、航路，或搜尋時才取得
- **GTFS 匯入** — 船與離島巴士使用 GTFS 時刻表，後端每天檢查新版本，到生效日自動切換
- **圖示** — [Lucide Icons](https://lucide.dev/)（以行內 SVG 嵌入）

### 目錄結構

```
tsukinkanban-web/
├── index.html              # 進入點（App Shell）
├── manifest.json           # PWA 設定檔
├── css/                    # 樣式表（變數、動畫、巴士、船等各 UI 元件）
├── js/                     # 應用程式邏輯
│   ├── script.js           #   主引擎（卡片繪製、燈號彙整與操作）
│   ├── header.js           #   頂部列、搜尋、膠囊按鈕模式切換
│   ├── buses.js            #   巴士（搜尋、到站預測、站牌面板）
│   ├── bus-timetable.js    #   巴士站牌時刻表
│   ├── ship.js             #   船（東海汽船航路卡片、運航資訊）
│   ├── flights.js          #   航班卡片
│   ├── add-panel.js        #   新增卡片
│   ├── edit-routes.js      #   編輯卡片內路線
│   ├── personalization.js  #   卡片個人化與復原
│   ├── history-daemon.js   #   取得運行歷史
│   ├── data-sources.js     #   資料提供狀態、提供結束的說明
│   ├── clock.js            #   同步時鐘
│   └── ...
├── data/                   # 路線字典、選單文案、裝置內資料庫
└── img/                    # Logo 與圖片
```

### 本機執行

不需要建置，用任何靜態伺服器指向專案根目錄即可：

```bash
# 方法 1：Python
python3 -m http.server 8000

# 方法 2：用 VS Code 的 Live Server 擴充功能開啟 index.html
```

在瀏覽器打開 `http://localhost:8000` 即可運作（取得即時運行資料需要能連上外部 API）。
